# BOC 合约策略

## 交易方向模式

`trade_mode` 控制开仓方向：

| 值 | 模式 | 行为 |
| --- | --- | --- |
| `0` | 只做多 | 信号触发后只开多仓 |
| `1` | 只做空 | 信号触发后只开空仓 |
| `2` | 双向 | 同一交易对同时开多仓和空仓 |
| `3` | 趋势判断 | 比较滚动窗口前后两段 K 线的最高价总和，后段较大时做多，否则做空 |

趋势判断使用 `kline_count` 根已收盘的 5 分钟 K 线。窗口数量为偶数时平均分成前后两段；为奇数时，前段比后段多一根，并将最后一根 K 线的最高价再计入后段一次。例如窗口为 11 根时，前段使用第 1 至第 6 根，后段使用第 7 至第 11 根并重复第 11 根。

`max_symbols` 限制同时持有的方向仓位总数。单向模式中每个交易对占一个仓位；双向模式中同一交易对的多仓和空仓各占一个仓位。例如 `trade_mode: 2`、`max_symbols: 2` 最多容纳一组多空仓位。

## 策略参数

- `kline_count`：滚动窗口中的 5 分钟 K 线数量。`12` 约为 1 小时，`24` 约为 2 小时。
- `min_move_rate`：触发交易的最低窗口振幅，计算方式为 `(最高价 - 最低价) / 最低价`。例如 `0.2` 表示严格超过 20%。
- `trade_interval_seconds`：检查交易信号的间隔秒数。
- `trade_usdt`：每个方向的目标名义仓位金额会乘以 `leverage` 计算。
- `take_profit_rate`：止盈比例。
- `stop_loss_rate`：止损比例。
- `entry_reprice_seconds`：GTX 入场挂单等待多久后撤单并按最新行情重挂。
- `entry_timeout_seconds`：入场挂单总等待时长。到期后停止重挂，已成交部分仍会设置止盈和止损保护。

入场使用 GTX（Post Only）限价单，避免以吃单方式成交。GTX 价格若会立即成交，交易所会拒绝订单，程序会向被动方向移动一个价格档位后重试。当前止盈和止损由交易所条件市价单执行。

配置示例见 [`config.sample.json`](config.sample.json)。将其复制为 `config.json` 并填入账户参数后，可使用仓库中的 `docker-compose.yaml` 部署。
