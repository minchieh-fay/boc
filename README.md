# BOC 合约策略

## 交易方向模式

策略固定使用追涨杀跌信号，`trade_mode` 控制允许的开仓方向：

| 值 | 模式 | 行为 |
| --- | --- | --- |
| `1` | 追涨杀跌 + 只追涨 | 趋势向上时只开多仓 |
| `2` | 追涨杀跌 + 只杀跌 | 趋势向下时只开空仓 |
| `3` | 追涨杀跌 + 都做 | 上涨趋势时开多仓，下跌趋势时开空仓 |

趋势判断使用 `kline_count` 根已收盘的 5 分钟 K 线，分别比较前后两段每根 K 线的 `high + low` 总和。后段总和较大时判定为上涨趋势，否则判定为下跌趋势。窗口数量为奇数时，前段比后段多一根，并将最后一根 K 线再计入后段一次，使两段数量相同。

`max_symbols` 限制同时持有的方向仓位总数。每个交易对每次信号只开一个方向的仓位。

## 策略参数

- `kline_count`：滚动窗口中的 5 分钟 K 线数量。`12` 约为 1 小时，`24` 约为 2 小时。
- `min_move_rate`：触发交易的最低窗口振幅，计算方式为 `(最高价 - 最低价) / 最低价`。例如 `0.2` 表示严格超过 20%。
- `trade_interval_seconds`：检查交易信号的间隔秒数。
- `trade_usdt`：每个方向的目标名义仓位金额会乘以 `leverage` 计算。
- `take_profit_rate`：止盈比例。
- `stop_loss_rate`：止损比例。
- `entry_reprice_seconds`：GTX 入场挂单等待多久后撤单并按最新行情重挂。
- `entry_timeout_seconds`：入场挂单总等待时长；空头退出挂单也按此时长持续重挂，每轮管理周期继续尝试未完成的退出。

入场和空头退出使用 GTX（Post Only）限价单，避免以吃单方式成交。GTX 价格若会立即成交，交易所会拒绝订单，程序会向被动方向移动一个价格档位后重试。

## 持仓管理

- 多头开仓后设置全量止损和一张部分止盈条件单。止盈数量按当前余仓的 10% 计算；若该笔名义金额低于 `trade_usdt * take_profit_rate`，则提高数量满足金额门槛，余仓总金额低于门槛时对余仓全部止盈。
- 多头部分止盈成交后，以最新成交报价为基准重设止盈价和全量止损价，并为余仓创建下一张部分止盈单。
- 空头开仓后只设置全量止损。价格达到开仓均价对应的止盈幅度后检查趋势；趋势继续向下时按最新报价更新止损，趋势转向时以 GTX 限价单平仓并持续重挂。
- 持仓方向、数量和保护单编号写入 `data/position_state.json`，程序重启后据此继续管理本程序创建的仓位。
- 趋势和止盈条件每 `trade_interval_seconds` 秒检查一次；止损保护由交易所条件单执行。

配置示例见 [`config.sample.json`](config.sample.json)。将其复制为 `config.json` 并填入账户参数后，可使用仓库中的 `docker-compose.yaml` 部署。
